ACAV Docker/Podman Demo Image - User Guide

ACAV (Aurora Clang AST Viewer) - an Abstract Syntax Tree visualization tool for Clang's C-family languages

Prerequisites

Required Software:

  • Docker or Podman (container runtime)
  • X11 Server (for GUI application)
    • Linux: Pre-installed with most desktop environments
    • macOS: XQuartz
    • Windows: VcXsrv or Xming

Note on Version Numbers: Throughout this document, examples use v1.0.0 as a placeholder. Replace this with your actual version number from the tar archive filename (e.g., if you have acav-v1.2.3.tar.gz, use v1.2.3 in all commands).

Quick Start

For the easiest experience, use the provided demo script:

./scripts/run_demo

This script automatically:

  • Detects docker or podman
  • Loads the image if needed
  • Sets up X11 display forwarding
  • Launches the GUI with example files

For a more configurable launcher, use:

./scripts/run_acav_container.sh -- \
acav -c /opt/acav/examples/compile_commands.json

This helper also supports --runtime, --image, --tar, --workspace, --user, --shell, and --no-desktop.

Run program manually

Step 0: Set the Variables

Set several variables that are used by the examples in the remainder of this document.

Set the ACAV version used in later commands:

acav_version=vX.Y.Z

Set whether the docker or podman program is used. Both programs have a mostly compatible CLI, so either should work:

docker=docker

or

docker=podman

Set any security options needed for Podman/Docker.

On systems that use SELinux (such as Fedora Linux) use:

security_opts="--security-opt label=disable"

If no platform-specific security options are needed, simply use:

security_opts=

Step 1: Load the Image

$docker load -i acav-$acav_version.tar.gz

Note: Some Podman setups may tag local images as localhost/acav:$acav_version.

Step 2: Verify

# List images
$docker images | grep acav
# Expected output:
# acav v1.0.0 ... 1.2GB # size may be different

Step 3: Quick Test

$docker run --rm $security_opts acav:$acav_version make-ast --help

If you see the help message, the image is loaded correctly.

Running the GUI Application

Automatic Display Options

We provide a helper script scripts/print_desktop_options that detects your desktop environment and prints required container options. It supports:

  • Linux X11 and Wayland
  • WSL2/WSLg detection
  • macOS host display resolution for Docker/Podman
  • Automatic QT_QPA_PLATFORM and SELinux-related runtime options
desktop_options=$(./scripts/print_desktop_options)
$docker run --rm -it $security_opts $desktop_options \
acav:$acav_version acav -c /opt/acav/examples/compile_commands.json

Or use the wrapper script:

./scripts/run_acav_container.sh -i acav:$acav_version -- \
acav -c /opt/acav/examples/compile_commands.json

If you prefer to set options manually:

$docker run --rm -it \
$security_opts \
-v /tmp/.X11-unix:/tmp/.X11-unix \
-e DISPLAY=$DISPLAY \
-e HOME=$HOME \
-v $XAUTHORITY:$HOME/.Xauthority \
acav:$acav_version acav -c /opt/acav/examples/compile_commands.json

What You Should See

  1. A GUI window appears
  2. Left panel shows a source file list with calculator.cpp
  3. Double-click calculator.cpp to generate and view its AST
  4. Click AST nodes to highlight corresponding source code

For detailed usage instructions, see the included ACAV_USER_MANUAL.md file.

Get Help

$docker run --rm $security_opts acav:$acav_version make-ast --help
$docker run --rm $security_opts acav:$acav_version query-dependencies --help

Working with Your Own Code

Mount your project directory and point to your compile_commands.json:

./scripts/run_acav_container.sh \
-i acav:$acav_version \
--workspace /path/to/your/project \
-- \
acav -c /path/to/your/project/compile_commands.json

If you prefer manual docker/podman run, the previous print_desktop_options approach still works.

Important: Paths in compile_commands.json must match container paths. You may need to edit the JSON file to use /workspace/... paths:

[
{
"directory": "/workspace",
"command": "clang++ -std=c++20 -c /workspace/main.cpp",
"file": "/workspace/main.cpp"
}
]

The runtime image does not bundle your project compiler, C++ standard library headers, SDKs, or cross toolchains. If your compilation database relies on implicit toolchain include paths, make sure the recorded compiler is available inside the container, or regenerate the database in the same container/mount layout you use for ACAV.

Troubleshooting

X11 Issues

"Cannot open display" or "No protocol specified"

Verify DISPLAY and XAUTHORITY are set:

echo $DISPLAY
echo $XAUTHORITY

If $XAUTHORITY is not set, set it manually:

export XAUTHORITY=$HOME/.Xauthority

Image Naming Issues

If manual commands fail with an image-name mismatch (acav:... vs localhost/acav:...), use scripts/run_acav_container.sh. It resolves both forms automatically.

Inside the Docker Image

Binaries (in /opt/acav/bin/):

  • acav: GUI application for interactive AST visualization
  • make-ast: CLI tool to generate AST JSON files
  • query-dependencies: CLI tool to analyze header dependencies

Example Files (in /opt/acav/examples/):

  • calculator.cpp / calculator.hpp: Sample C++ code
  • compile_commands.json: Compilation database for examples
